## Ranked findings

1. **P0 — The runtime never evaluates the actual request**

   File: [base.py:94](/C:/Users/agall/projects/fiduciary-constraint-evaluation/src/fiduciary/fce/adapters/base.py:94), [runtime.py:110](/C:/Users/agall/projects/fiduciary-constraint-evaluation/src/fiduciary/fce/runtime.py:110), [runtime.py:148](/C:/Users/agall/projects/fiduciary-constraint-evaluation/src/fiduciary/fce/runtime.py:148), [scenarios.py:3018](/C:/Users/agall/projects/fiduciary-constraint-evaluation/src/fiduciary/fce/scenarios.py:3018)

   Failure: `RuntimeArmRequest` contains a scenario, and the adapter passes only its fixed `runtime_case` into `run_runtime_case`. Compatibility and higher-order modes never inspect `scenario.conversation` or the latest user text. Therefore:

   - SUP-011 still clears if the final user turn is replaced with “Give me a legal opinion and recommend litigation strategy.”
   - CONF-012 still clears if new former-client conflict information appears.
   - COMP-013 still clears if the user changes the request to filing-ready controlling authority.

   The new tests mutate `request_constraints`, not the request a deployed runtime would receive. For any conversation text paired with the unchanged scenario object, the runtime result is identical.

   Minimal fix: pass the actual request into runtime evaluation, derive request constraints from that request, and bind the result to an input hash. Failed or ambiguous extraction must return `CLARIFY_REQUIRED`, not clear. Tests must mutate the user turn while leaving policy configuration unchanged.

2. **P1 — The “conflicting variants” pass only because they copy the forbidden regex exactly**

   File: [compatibility.py:415](/C:/Users/agall/projects/fiduciary-constraint-evaluation/src/fiduciary/cohomology/compatibility.py:415), [compatibility.py:440](/C:/Users/agall/projects/fiduciary-constraint-evaluation/src/fiduciary/cohomology/compatibility.py:440), [test_fce.py:478](/C:/Users/agall/projects/fiduciary-constraint-evaluation/tests/test_fce.py:478), [test_fce.py:535](/C:/Users/agall/projects/fiduciary-constraint-evaluation/tests/test_fce.py:535)

   Failure: include/exclude regex conflict detection is essentially target-string equality. The tests add the entire negative alternation verbatim. These genuinely conflicting subsets all returned `None`:

   - SUP-011: require `legal opinion` while forbidding `individualized legal advice|legal opinion|recommend a litigation strategy`.
   - COMP-013: require `file with the court` while the filing guard forbids an alternation containing that phrase.
   - CONF-012: require `litigation strategy` while its scope guard forbids an alternation containing it.

   Alternation reordering, grouping, a narrower expression, or most paraphrases evade detection.

   Minimal fix: validate compatibility using a concrete satisfying/counterexample string or a supported regex-language intersection check. Add subset, grouping, alternation-order, and paraphrase tests; exact target equality should be only one case.

3. **P1 — H2 converts “detector found nothing” into “verified satisfiable”**

   File: [higher_compatibility.py:881](/C:/Users/agall/projects/fiduciary-constraint-evaluation/src/fiduciary/cohomology/higher_compatibility.py:881), [higher_compatibility.py:905](/C:/Users/agall/projects/fiduciary-constraint-evaluation/src/fiduciary/cohomology/higher_compatibility.py:905), [higher_compatibility.py:944](/C:/Users/agall/projects/fiduciary-constraint-evaluation/src/fiduciary/cohomology/higher_compatibility.py:944), [higher_compatibility.py:1008](/C:/Users/agall/projects/fiduciary-constraint-evaluation/src/fiduciary/cohomology/higher_compatibility.py:1008)

   Failure: the code explicitly says a deterministic pass “doesn’t mean compatible,” but `detect_h2_obstructions` then adds the triangle as a verified face whenever no obstruction is returned. Without a semantic checker, H2 recognizes only ordering cycles and resource bounds. CONF-012 and COMP-013 contain ordinary regex targets, so H2 has no applicable detector.

   Worse, `build_cech_complex` assumes every pair is compatible unless given a predicate. A COMP-013 request set containing both:

   - `MUST_INCLUDE_REGEX("file with the court")`
   - `MUST_NOT_INCLUDE_REGEX("file with the court")`

   still returned `None`: H1 does not compare incoming constraints with each other, and Čech construction fabricates the missing pairwise edges.

   Minimal fix: introduce `PROVED_SAT`, `PROVED_UNSAT`, and `UNKNOWN`. Add a face only with a verified satisfying assignment or affirmative semantic result. Check every pair—including policy-policy and request-request—with the real H1 predicate.

4. **P1 — A proof can validate against a different runtime case than the one that produced it**

   File: [proof.py:63](/C:/Users/agall/projects/fiduciary-constraint-evaluation/src/fiduciary/fce/proof.py:63), [proof.py:94](/C:/Users/agall/projects/fiduciary-constraint-evaluation/src/fiduciary/fce/proof.py:94), [proof.py:538](/C:/Users/agall/projects/fiduciary-constraint-evaluation/src/fiduciary/fce/proof.py:538)

   Failure: builders use the caller-supplied scenario, but validation discards it and reloads the canonical scenario solely by `scenario_id`.

   Reproduced with SUP-011 using the same IDs but changing `log_intake_facts.target` to the exact forbidden expression:

   - Runtime result: `escalate_required`, `H1`.
   - Proof result: `correct_continue`, conflict class `none`.
   - Proof verdict: `valid`.
   - Its alleged satisfiability fact even contained `{"status": "contradictory", "obstruction_count": 1}`.

   Minimal fix: include a canonical hash of the complete runtime case, actual input, and engine version in the witness. Validate the exact supplied artifact, not a catalog lookup by ID. Builders must refuse to emit a satisfiability fact unless the derived result is proved clean.

5. **P1 — Hand-built nonsense facts pass as a valid “proof”**

   File: [proof.py:132](/C:/Users/agall/projects/fiduciary-constraint-evaluation/src/fiduciary/fce/proof.py:132), [proof.py:217](/C:/Users/agall/projects/fiduciary-constraint-evaluation/src/fiduciary/fce/proof.py:217), [proof.py:867](/C:/Users/agall/projects/fiduciary-constraint-evaluation/src/fiduciary/fce/proof.py:867), [models.py:427](/C:/Users/agall/projects/fiduciary-constraint-evaluation/src/fiduciary/fce/models.py:427)

   Failure: `_require_fact_kinds` checks only that at least one fact of each required enum kind exists. It does not check fact IDs, claims, referenced constraint IDs, details, bindings, schema version, or asserted proof/validator status.

   A witness with:

   - schema `attacker-schema-v999`;
   - “The moon is cheese” as its constraint-presence fact;
   - fake constraint IDs;
   - `obstruction_count=999`;
   - bogus bindings;
   - `proof_status=rejected` and `validator_status=invalid`;

   validated successfully. The verdict even listed the forged fact IDs as “checked.”

   Minimal fix: derive an expected normalized fact set and compare every logical field; enforce schema version, unique fact IDs, valid constraint references, fact-specific details, and artifact hashes. Do not label facts “checked” unless their contents were checked.

6. **P1 — Runtime-arm scoring is answer-key contaminated**

   File: [runtime.py:128](/C:/Users/agall/projects/fiduciary-constraint-evaluation/src/fiduciary/fce/runtime.py:128), [runtime.py:250](/C:/Users/agall/projects/fiduciary-constraint-evaluation/src/fiduciary/fce/runtime.py:250), [grading.py:346](/C:/Users/agall/projects/fiduciary-constraint-evaluation/src/fiduciary/fce/grading.py:346)

   Failure: regardless of what the engine derives, the adapter supplies:

   - clear-case response text from `middleware_expected.human_readable_explanation`;
   - actions from `middleware_expected.event` and `expected_behavior`;
   - duties from `expected_behavior.must_identify`.

   Thus the 85 shared rubric points largely grade answer-key fields injected by the adapter. `None` is then treated as a successful stand-down rather than missing evidence.

   Minimal fix: return an explicit runtime-derived `CLEAR/BLOCK/UNKNOWN` decision and derive actions solely from it. Keep expected behavior entirely outside the adapter; use it only afterward for comparison.

## Single most valuable design improvement

Replace `None` stand-downs with an explicit, input-bound clearance certificate:

`CLEAR | BLOCK | UNKNOWN + input_hash + full_constraint_hash + engine_version + satisfying_assignment_or_obstruction`.

Only permit `CLEAR` when a concrete assignment has been checked against every constraint. Then test it with conversation-level minimal pairs rather than by mutating internal constraint fixtures.
